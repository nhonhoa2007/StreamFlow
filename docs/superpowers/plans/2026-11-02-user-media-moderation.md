# User Media Uploads and Admin Moderation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let authenticated users upload actual audio/video, preview processed submissions privately, and publish playable content only after administrator approval.

**Architecture:** Extend the existing modular monolith and independent media worker. PostgreSQL owns lifecycle/ownership/review decisions and durable tasks; BullMQ executes retryable processing/publication/cleanup work, using a private S3 bucket for originals and review output and the existing public bucket for approved derivatives. A complete browser workflow spans creator upload/management, administrator review, and audio/video playback.

**Tech Stack:** TypeScript, pnpm 10.33.2, Turborepo, NestJS 11/Fastify, PostgreSQL 16/Drizzle, Redis/BullMQ, FFmpeg/FFprobe, AWS SDK v3, Next.js 15/React 19, Zod, Vitest, existing Node test infrastructure.

**Spec:** `docs/superpowers/specs/2026-11-02-user-media-moderation-design.md` — approved on 2026-11-02. Read the whole spec before this plan. This is one connected feature: privacy, processing, decisions, and publication share a lifecycle and cannot ship as independent products. Tasks still have independently testable deliverables.

## Global Constraints

- Process first, review second; processing success must never publish content.
- Public eligibility is `deleted_at IS NULL AND processingStatus = READY AND moderationStatus = APPROVED AND publicationStatus = PUBLISHED`.
- Preserve existing NestJS/Fastify, PostgreSQL/Drizzle, BullMQ/Redis, FFmpeg, Next.js, and shared Zod contracts; no external media processing service.
- Keep `STORAGE_BUCKET_NAME=stream-flow` for public approved derivatives. Add required `STORAGE_PRIVATE_BUCKET_NAME=stream-flow-private`; never expose originals or unreviewed derivatives through a public bucket.
- Video maximum 1 GiB; audio maximum 100 MiB; 3 unfinished uploads/user; 2 GiB source bytes/user/day; video duration 2 hours, audio duration 30 minutes. Make these configurable defaults.
- Private preview capability lifetime: 15 minutes. Renew before expiry and preserve playback position.
- Metadata edits are allowed only in moderation DRAFT/REJECTED with processing AWAITING_UPLOAD/FAILED/READY and no active processing/publication task. Edits during QUEUED/PROCESSING return 409.
- Reviewed/published content is immutable in this MVP. Replacing a file creates a new submission. ADMIN may review their own submission; no second administrator is required.
- Preserve user data and existing uncommitted CORS changes in `backend/apps/api/src/app.module.ts`. Add migrations; do not reset databases or rewrite applied migrations.
- Never print/commit `.env`, credentials, private capability tokens, or public deployment secrets. Never automatically delete/move existing remote R2 data.
- Conventional Commits in English; no AI attribution trailers/footers. Stage only files owned by each task.
- Tests use isolated PostgreSQL/Redis/MinIO fixtures. Real R2 uploads/cleanup, bucket provisioning, legacy object migration, and deployment require explicit authorization for that rollout action.
- At execution start, use `superpowers:using-git-worktrees`; read the approved spec/plan and preserve local CORS changes through integration. No implementation occurs during this planning turn.

## Review Focus

1. Two users guessing another user's media/upload IDs must get 404 without metadata, source URLs, or preview capabilities — Task 3 and Task 6 tests.
2. A Redis outage or worker crash between a successful storage operation and DB commit must leave recoverable, idempotent work — Task 4, Task 5, Task 7 tests.
3. A private HLS preview must authorize every rendition/segment/range request, including native playback, expired tokens, and encoded traversal — Task 6 tests and Task 12 browser checks.
4. Metadata edits, review decisions, and deletion racing processing/publication must not invalidate a live job silently or resurrect unapproved content — Task 1 and Task 7 tests.
5. Audio-only, tiny portrait video, video without audio, and a changed source behind an unexpired upload URL must either play correctly or fail explicitly — Task 5 tests.

Create/export these shared names in Tasks 1/2 before consumers use them:

```ts
type Actor = { id: string; role: "USER" | "ADMIN" };
type ProcessingStatus = "AWAITING_UPLOAD" | "QUEUED" | "PROCESSING" | "READY" | "FAILED";
type ModerationStatus = "DRAFT" | "PENDING_REVIEW" | "APPROVED" | "REJECTED";
type PublicationStatus = "UNPUBLISHED" | "PUBLISHING" | "PUBLISHED" | "FAILED" | "REMOVING" | "REMOVED";
type VersionedMediaInput = { mediaId: string; expectedVersion: number };
type MediaTaskKind = "TRANSCODE" | "PUBLISH" | "DELETE" | "INVALIDATE_CACHE";
type DerivativeObject = {
  kind: "HLS_PLAYLIST" | "HLS_SEGMENT" | "THUMBNAIL";
  relativePath: string; contentType: string; sizeBytes: number;
};
type SourceSnapshot = {
  assetId: string; mediaId: string; bucket: string; key: string;
  etag: string; sizeBytes: number; mimeType: string; mediaVersion: number;
};
```

`SubmissionDetail` is the shared Zod-inferred creator/admin DTO: media ID/type/title/description/owner/version; processing/moderation/publication states; progress/error/rejection reason; duration; timestamps; nullable processing run ID. Do not put raw source keys or permanent private URLs in it. `SubmissionPage` is `{ items: SubmissionDetail[], nextCursor: string | null, hasMore: boolean }`.

`MediaTaskPayload` is a discriminated union by `kind`. TRANSCODE contains mediaId/mediaVersion/runId/sourceAssetId; PUBLISH contains mediaId/mediaVersion/runId/reviewId; DELETE identifies a media, processing run, or expired upload session with recorded prefixes; INVALIDATE_CACHE identifies mediaId. The SQL task ID is also included when dispatched. Do not use an untyped arbitrary key from HTTP input.

`MediaTaskRow` is the exported inferred select type of `mediaTasksTable`; claimed tasks include the current lease token used by handlers. `StorageSettings`, `ObjectMetadata`, and `ObjectReadResult` are exported by the shared storage package. StorageSettings contains provider/endpoint/privateBucket/publicBucket/publicUrl/accessKeyId/secretAccessKey; credentials are server-only. `PreviewResponse` is `{ manifest: PlaybackManifestResponse; expiresAt: string }`, exported by shared contracts; its manifest uses the API capability URL rather than a public storage URL.
